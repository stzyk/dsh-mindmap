# dsh-mindmap — 决策追踪（docs/plan.md）

> 一句话需求：「创建一个 dsh 插件，实现简易思维导图功能，能新增保存，能转换成 markdown」
> 环境：`~/.dsh/profiles/web`（开发 profile）+ 端口 3099（隔离，不碰 desktop-web/3080）
> 日期：2026-11-05

---

## 1. 需求 → 能力面

| 用户说的 | 能力面 | 落点 |
|---|---|---|
| 「思维导图功能」 | 浏览器 UI：一个完整面板 | `main` 插槽（keyed） |
| 「能在界面上找到它」 | 侧边栏入口 | `sidebar.panellist` 插槽（list） |
| 「新增」 | 新建 / 加节点 / 缩进 / 删除 | 画布键盘流 |
| 「保存」 | 持久化到磁盘 | Host RPC + `storages/dsh-mindmap.json` |
| 「转换成 markdown」 | 两种形态导出 + 复制/下载 | Host `docs.markdown` + 客户端面板 |

**形态决策**：`bundle-client`（Node 半区 + 浏览器 client）。
理由：纯 `pure` 没有界面，做不了画布；`bundle` 无 client 同理。

---

## 2. 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 挂哪个插槽 | `main` + `sidebar.panellist` | 导图需要专心看，不该是压在会话上的浮层。两者用同一个 id 配对（ui-sidebar 的 `SidebarPanelMetadata.id` 就是 main 的 key） |
| 数据存哪 | Host `storages/dsh-mindmap.json` | 存 localStorage 换浏览器就没了，而且命令读不到。存 Host 才能做 `/mindmap markdown` |
| 编辑交互 | **大纲键盘流**，非拖拽 | 真实使用 90% 是"加一个想法/改一句话/挪一层"，绑键盘比拖拽快一个数量级。键位与 XMind/Workflowly/幕布一致，零学习成本 |
| 保存时机 | 防抖 600ms + 显式保存 + 切文档前 flush | 逐键 round-trip 会被中文输入法打满写盘队列，光标还会抖 |
| 布局算法 | 右向树，父节点对齐**首尾子节点中心** | 不用子树块加权重心：分支大小不均时重心会把父节点拉向"重"的那侧，父节点就不在自己两个分支中间了 |
| Markdown 两种形态 | `headings`（默认）/ `list` | headings 适合当文章骨架；list 适合贴进大纲工具 / 喂模型。深处（>6 级）自动降级成列表，保证任何渲染器都合法 |
| 转换在哪算 | Host `docs.markdown` 端点 | 命令导出的和按钮导出的必须逐字节一致，两处实现迟早跑偏 |
| 零依赖 | 只用 Node 内建 + React（平台提供） | 契约要求不声明 `@deepseek-ai/*`；额外依赖会让 git 源安装变脆 |
| 坏数据策略 | 自愈，永不抛错 | 一份坏 JSON 不该让宿主起不来：备份成 `.corrupt-<ts>` 后从空列表继续 |
| 剪贴板失败 | 提示手动全选文本框 | 局域网 http 是非安全上下文，`navigator.clipboard` 会被拒。不能假装成功 |

### 4.2b 根节点配色缺陷（用户反馈，v0.1.1 修复）

**现象**：主题节点（根）是一整块纯黑，文字与背景同色，看不见也输不进去。

**根因有两层**：

1. 根节点原本靠"反色"突出：`background: var(--dsw-alias-label-primary)`、
   `color: var(--dsw-alias-bg-base)`——把**文字色当背景**、把**页面底色当前景**。
   这在默认主题下恰好能看，但 `label-*` 与 `bg-*` 是两个语义独立的变量族，
   在 `data-dsh-skin=xp` 皮肤下不再成对，于是得到纯黑底 + 近黑字。
2. 节点内联编辑框只写了 `color: inherit` + `background: transparent`。
   换肤后 input 的背景被宿主规则接管成白色，而继承来的前景是浅色 → 白底白字，
   打进去的字看不见（但 `value` 是对的，所以功能测试全绿）。

**修复**：
- 根节点改为「加粗 + `bg-layer-3` 填充 + `border-l3` 描边」表达主节点，
  前景恒为 `label-primary`。不再依赖任何变量配对，换任何皮肤都由宿主保证对比度。
- 编辑框显式声明 `color: var(--dsw-alias-label-primary)`、`caret-color: currentColor`、
  以及长写 `background-color`（简写 `background` 会被皮肤规则连带重置）。
- 编辑态去掉节点外壳的描边与阴影，只留输入框自己的内嵌焦点框，消除双层边框。

**为什么以前的测试没抓到**：所有断言（节点数、文字内容、Markdown 输出、
复制结果）全部通过——数据是对的，只是**画错了**。这类问题只能靠
① 人眼看截图 ② 把"看得见"变成可计算的断言。

**新增的两道护栏**：
- `verify/smoke.py` 增加 **5b / 5c**：用 WCAG 相对亮度公式计算根节点文字与背景、
  以及编辑框文字与实际可视底色的对比度，低于 3.0 即失败。修复后实测 17.21 / 21.00。
- `scripts/test-core.mjs` 增加 3 条静态样式断言：禁止任何规则把 `label-*` 用作
  `background`、根节点前景必须来自 label 系列、编辑框必须显式声明前景与 caret。
  已用变异测试验证：把修复回退成反色写法，这 3 条里有 2 条立即失败。

### 4.2c Tab 键位缺陷（用户反馈，v0.1.2 修复）

**现象**：「Tab 没办法增加子节点」。

**根因**：两件事叠加，第二件更严重。

1. 键位设计照搬了大纲编辑器（幕布 / Workflowly）的习惯：`Tab` = **缩进**，
   `Shift+Tab` = 取消缩进。但思维导图用户的直觉是「Tab 加子节点」，按下去没有新节点，
   体感就是"这个键坏了"。
2. **`addChild()` 写好了却没有任何入口**——它既没绑到任何按键，也没有按钮。
   也就是说"加子节点"这个核心能力当时**根本不可达**，只能靠"先加同级再缩进"绕路。

**修复**：
- `Tab` → **加子节点**（导图直觉）；`Shift+Tab` → 减一级（大纲直觉保留）；
- 缩进/取消改绑 `Alt+→` / `Alt+←`；
- 画布上方加一条常驻操作条：`+ 子节点` / `+ 同级`，鼠标用户也有可见入口；
- 提示条同步更新。

**顺带修掉的测试问题**：原 4b 断言的是「Tab 缩进」，语义已变；重写为 4b/4c/4c2/4d 四条，
其中 4c 必须用 **depth≥2** 的节点验证 outdent —— 第一层节点的父是根，根没有兄弟，
语义上就是不能再减，用 depth=1 去测会误判成缺陷。

**新增断言**：4b（Tab 后节点数 +1 且新节点 depth 正确）、4c（depth 2→1）、
4c2（第一层 Shift+Tab 被安全拒绝、节点不消失）、4d（按钮点击也能加）。

### 4.2d 自由拖动（用户需求，v0.1.3 新增）

原计划把"自由拖拽"列为**不做**（理由：命中测试 + 落点预览 + 自动滚动的成本高）。
用户明确要求后重新评估：真正必要的只是「位置」，不涉及改层级或碰撞检测，成本可接受。

**设计**：
- `MindNode.position?: {x, y}` —— 可选字段。**不填 = 自动布局**，填了 = 固定坐标。
  这样"拖动"是逐节点可选的，不会因为拖了一个节点就让整张图失去自动排版。
- 坐标只影响画法，不影响结构：`toMarkdown()` 的输出与拖动前完全一致（有单测锁死）。
- 拖动用 Pointer Events + `setPointerCapture`：鼠标、触控板、触屏一套代码；
  指针移出元素后仍能收到事件，拖到画布外松手不会卡在拖动中。
- 3px 阈值区分"点击"与"拖动"：避免手抖把位置锁死成手动。
- 拖动过程用 `dragPreview` 局部 state 渲染，**松手才写回文档**并触发一次保存。
- 按 `zoom` 换算坐标：`clientX/Y` 是屏幕像素，画布有 CSS transform scale。

**实现中修掉的两个坑**：
1. 连线不跟随：节点用预览坐标渲染，但 `layout.links` 还是旧坐标，出现
   "节点走了、线还连着原位"的错位。改成按预览坐标重算端点。
   （用 `getPointAtLength` 验过：拖动中连线终点与节点左中点距离 = 0）
2. 拖动根节点会"整棵树消失"的隐患：如果手动节点直接 return 不排子树，
   根节点一拖全图就空了。现在手动节点只改自身坐标，子树照常从其新位置展开。

**新增断言**（冒烟 5d 系列，用真实 `mouse.down/move/up`，不是直接改数据）：
5d 拖动写入坐标、5d2 层级不变、5d3 拖动根节点后节点数不变、5d4「重新排版」清空坐标。
单测侧另有 9 条覆盖 position 的保留/校验/布局分支。

### 4.2e 节点图片（用户需求，v0.2.0 新增）

支持两种形态：**图文节点**（文字 + 图片）与**纯图片节点**（无文字只有图）。

**存储策略（关键决策）**：字节存磁盘、元数据进 JSON。

- 图片存 `storages/dsh-mindmap-assets/<id>.<ext>`，文档里只留 `id / type / 宽高 / 说明`。
- 为什么不塞 base64 进 JSON：用户放十张手机照片就是几十 MB，而这份 JSON
  每次保存都要整份序列化一遍，编辑会越来越卡。
- 三道安全约束（都会直接拼进磁盘路径）：id 白名单 `[A-Za-z0-9._-]{1,80}`
  （挡路径穿越）、MIME 白名单（**不收 svg**，它可含脚本）、单张 8MB 上限。
- **以魔数为准**：客户端声明的 MIME 只作参考，实际类型从文件头探测
  （PNG/JPEG/GIF/WebP 各写了 sniff 与尺寸解析），顺带挡住"改后缀"。

**三个上传入口**：粘贴剪贴板、拖文件到画布、点「+ 图片」选文件。
剪贴板监听挂在 document 上而不是画布元素：用户的实际操作是"在面板里 Ctrl+V"，
焦点未必在画布上。

**显示用 object URL 而非 data URI**：几十张图时 data URI 会让内存翻倍且切文档回收不掉；
object URL 卸载时 revoke 即可。按需取 + 缓存，不一次性全拉。

**Markdown 两种模式**（用户选的"两者都给，默认相对路径"）：
- 默认 `![说明](assets/<id>.png)` + 「导出图片」按钮单独下图片包
- 勾选「内嵌图片」→ base64 data URI，单文件可分享
- 查不到字节时**退回路径而不是丢图**

**实现中修掉的问题**：
1. 布局重叠：`spanOf` 原来统一用 `LAYOUT.nodeHeight` 占位，139px 高的图片节点
   被按 34px 占位，兄弟节点直接压在它身上。改成按真实 `contentSize().height` 占位。
2. **孤儿文件**：`reconcile()` 写好了却一次没调用（和之前 `addChild` 同一类错误——
   写了函数没接上）。实测：文档已删但 assets 里堆了 **7 个孤儿文件**。
   已接入两处：删除文档时清理"该文档独占且他人不再引用"的图片；启动时全量对账

**验证过的两个关键场景**（都用手工构造的文档 + 真实重启）：
- 图片被文档引用 → 重启后**文件保留**（不能误删在用的图）
- 删除文档 → 该图**被清理**（磁盘 1 → 0）

### 4.2f 撤销 / 重做（用户需求，v0.3.0 新增）

**粒度**：按操作步数（用户选定）。**范围**：只覆盖当前文档的编辑
（节点增删改、拖动、缩进、折叠、图片），不含改名与删文档——撤销"删除文档"
需要连图片字节一起恢复，超出这一层职责。

**用快照栈而不是命令栈**：
命令栈要为每种操作写一对 undo/redo（记住插在哪、旧坐标、整棵被删子树……），
漏一个就是"撤销后数据坏了"。快照只需要一次 `structuredClone`，任何新操作
自动获得撤销能力。代价用三道闸压住：只存树（不存标题/时间戳）、深度上限 100、
内容相同不入栈（`sameTree` 做结构比较）。

**键位**：`Cmd/Ctrl+Z` 撤销，`Cmd/Ctrl+Shift+Z` 或 `Cmd/Ctrl+Y` 重做。
监听挂在**画布**的 keydown 上而不是全局：用户可能同时在会话输入框里打字，
全局拦截会把宿主的 Ctrl+Z 吃掉。

**实现中修掉的真实缺陷**：
`create()` 里调了 `history.reset()`，但**忘了同步 `historyState`**——
新建文档后撤销按钮仍亮着（`canUndo: true`），可树里只有一个根节点，
点下去"无事可撤"。这是快照与内部状态不同步的典型表现，由冒烟测试
（断言 `historyState.canUndo === false`）抓到。

**测试写得很曲折，值得记录的经验**：
1. 一开始猜"撤销一次应该撤掉什么"，但 `Tab 加空节点`、`打字改名`、
   `Enter 提交并新建同级` 在历史里是**若干独立步**，具体几步取决于输入节奏。
   断言改成只钉**语义**：撤销让树回到先前状态、一路撤销能回到编辑前、一路重做能回去。
2. Playwright 点一个 `disabled` 按钮会一直等到 30s 超时，失败信息变成"超时"
   而不是"状态不对"。加了 `click_if_enabled()` 先判后点。
3. 前面几段用例互相污染（停在 Markdown 面板、选中别的节点），导致后面的失败
   全是"被连累"。加了 `reset_workspace()`：每段开头清空并新建一份只有根节点的文档。
4. 冒烟里硬编码的标题（`"冒烟测试导图"`）在用例改名后就不存在了，
   改成用**当前文档的真实标题**断言。

### 4.2g 双击图片查看大图（用户需求，v0.3.1 新增）

双击节点里的缩略图打开灯箱：遮罩 + 居中大图 + 缩放（25%~400%，`1:1` 复位）。
关闭方式有三种：点背景、按 `Esc`、双击大图自己。

**必须 portal 到 `document.body`**：画布是 `overflow: auto` 的滚动容器，
`position: fixed` 的子元素在里面会被裁剪或跟随滚动。灯箱要盖住整个面板，
只能挂 body；打开时锁 `body` 滚动并**记录原值**（关闭时还原，而不是设成 `''`
把宿主自己的 overflow 设置抹掉）。

**层级**：`2147483600`，比番茄钟插件的提醒卡片（`2147483000`）高，
避免两个插件的浮层互相遮挡。

**实现中修掉的两个缺陷**：
1. **点背景关不掉**：`.mm-lightbox-stage` 铺满整个灯箱且写了 `stopPropagation()`
   （本意是"别吃掉点击"），结果把关闭路径整个堵死——空白区域全是舞台，
   点哪儿都没反应，只剩 Esc 和按钮。改成舞台点击即关闭，图片自己
   `stopPropagation` 所以看图不会误关。
2. **双击缩略图会跳进节点改名**：事件冒泡到了节点的 `onDoubleClick`。
   图片的 `onDoubleClick` 里必须 `stopPropagation`。

**测试上的教训**：
5g 原本"承接 5e 的图片"，但 5f 里的 `reset_workspace()` 会清空并重建文档，
而 5f 跑在 5g 之前 —— 图片早就没了，报"画布上没有可点的图片"。
**每段自己造数据**，顺序就不再是隐式依赖。另外画布工具栏和 Markdown 面板里
都有「← 回到画布」，按文字取会点到不确定的那个，改成用 `data-mm-action` 精确定位。

### 4.2h Markdown 侧栏 + 反向编辑（用户需求，v0.4.0 新增）

Markdown 从"与画布互斥的视图"改成**右侧常驻、可收起的一栏**，两边都能改。

**双向**：
- 画布 → 侧栏：改树即重算生成的 Markdown（受控于 `doc` 引用变化）；
- 侧栏 → 画布：编辑后点「应用修改」，走 `mergeTree` 合并回树。

**为什么不做实时同步**：中文输入法一个词要按好几次键，边打边解析会让半截
语法（比如刚敲一个 `#`）频繁重建树，光标乱跳、历史栈爆炸。折中：显式按钮 +
失焦不自动应用（用户可能只是去点画布看一眼）。

**合并是这块最难的部分** —— `src/core/parse.ts`。用户改两个字，节点上的
图片、拖动位置、折叠状态、稳定 id 都必须保留。三级匹配：

1. **同路径同文字** → 直接复用；
2. **同路径同位置** → 用户改了这行的文字（保留了 id / 图片 / 位置）；
3. **新路径** → 新建；**消失的路径** → 删除。

**实现中修掉的 4 个合并缺陷**（每一个都会真实丢数据）：
1. **只按文字匹配** → 改一个字就被当成"删旧 + 建新"，图片和位置全丢。
   而改文字恰恰是编辑导图最高频的动作。（补了位置兜底）
2. **位置兜底没有闸** → 在前面插入新节点时，新节点占住序号 0，把原 0 号
   节点的图片错配到自己身上，且两个节点 id 重复。（加了"未被认领"
   + "旧文字在新结构里已不存在"两道判据）
3. **同名兄弟匹配到同一个旧节点** → 两个节点 id 重复、第二个被误判为删除。
   （路径匹配分支也要检查 claimedOld，并向 text#2 / text#3 递进查找）
4. **父节点改名后整棵子树"全删全建"** → 子节点在旧索引里的路径挂在
   **旧父文字**下，递归时若用新文字拼 trail 就一个都匹配不上。
   （递归时用匹配到的 `old.text` 拼 trail）

另外两个实现细节：
- **草稿跟随树**：用户在侧栏敲了字没应用，转头去画布加了节点 —— 侧栏若
  还显示旧草稿，看起来像"画布改动没同步"。现在树一变就丢弃草稿并**明确提示**，
  不静默丢用户的输入。
- **列表基准层级**：解析 `- a / - b / - c` 时每行都读栈长度，栈又会被 push
  撑大，层级算成 1/3/6/8。改成进列表时固定一次 `listBase`。

**测试教训**（都是测试自身的问题，不是功能的）：
- 侧栏打开后焦点在 textarea，`page.keyboard.press("Tab")` 会在 textarea 内跳转，
  不会在画布上加节点。必须先点画布抢回焦点。
- `reset_workspace` 之后焦点不在画布，直接按 Tab 会把焦点移出面板，
  整个界面看起来"消失"（诊断输出 `hasMmRoot: false, hasBar: false`）。

### 4.2i 节点属性（用户需求，v0.5.0 新增）

选中节点后在画布下方浮出属性栏：**配色 / 字号 / 字形 / 圆角 / 边框**。
可勾「含子节点」把设置应用到整支，也可「恢复默认」。

**只给预设色板，不给自由取色器。** 自由取色把"文字能不能看清"交给用户去保证，
而这插件已经因为"根节点反色"踩过一模一样的坑（换肤后变纯黑块）。色板每一组
都是**背景 + 前景配对**好的，对比度写进单测（≥ 4.5:1），换任何皮肤都不会糊。
字号 / 圆角 / 边框也取有限档位，避免用户选出一个撑爆布局的组合。

**数据里存的是色板 key（`"blue"`），不是硬编码色值。** 换色板时能平滑跟过去，
也不会因为用户填了个深色底就把文字压没。

**布局必须跟着字号走**：`contentSize` 改走 `effectiveFontSize`（节点自定义优先），
行高按 `fontSize × 1.38` 算。若布局用层级默认而渲染用自定义字号，
大字号节点的文字会溢出方框——这种"算的框装不下画的字"很难查。

**实现中修掉的 2 个真实缺陷**：
1. **改样式无法撤销**：`sameTree`（历史栈的"内容是否变化"判据）**漏了 style 字段**，
   只改样式会被判成"没变化"，`history.push` 直接 return —— 用户调了颜色，
   撤销键还是灰的，改错了退不回去。补上 6 个样式字段的比较 + 3 条回归单测。
2. **「恢复默认」按钮点不动**：它被宿主的**桌面宠物**浮层挡住
   （`.dsh-pet-root`，`position: fixed`，`z-index: 70`，整屏覆盖）。
   命中测试落在 pet 上，用户看得到按钮却点不到。
   **没有用 z-index 硬碰**（那是宿主的全局浮层，压过去可能影响别的交互），
   而是给面板头部留 96px 右侧安全区避开那块区域。
   冒烟加了 `5i10b` 用命中测试锁死"按钮必须命中自己"，防回归。

**测试教训**：属性面板的档位按钮只显示数字（字号 `13`、边框 `3`），
`has-text("3")` 会点错按钮。给每个 chip 加了 `data-mm-style`（组名）
+ `data-mm-value`（值），测试按组定位。**人看得懂的数字不是稳定的测试锚点。**

### 4.2j 画布缩放（用户需求，v0.6.0 新增）

操作条右侧：`−` / `百分比` / `+`，点百分比复位 100%。范围 25%–300%，11 个固定档位
（不用"每次乘 1.2"，否则连点几次会停在 121.55% 这种数上，回不到 100%）。
快捷键 `Cmd/Ctrl + = / − / 0`，以及 `Cmd/Ctrl + 滚轮`（锚在鼠标位置）。

**关键实现细节：`transform: scale()` 不改变布局尺寸。**

只加 transform 的话，放大后滚动条不会变长——右半边内容永远滚不到；缩小后又
留一片空白。所以中间加了一层 `.mm-canvas-scale`，把尺寸显式撑成
「内容 × 缩放」，内层再 scale。冒烟断言 `scrollH == scaleH` 锁住这点。

**锚点缩放**：先算出鼠标下的画布坐标，缩放后反解 `scrollLeft/scrollTop`，
让同一点停在同一屏幕位置。不锚定的话放大后视口会飘走，用户刚看的内容跑掉。

**滚轮监听必须用原生 `addEventListener`**：React 的 `onWheel` 注册成 passive，
里面 `preventDefault()` 被浏览器忽略；不拦的话浏览器会把**整个宿主页面**缩放掉。

**拖动在缩放下的坐标**：`dx / zoom` 换算。冒烟用精确断言锁死——
125% 时屏幕位移 (100,60) 必须产生画布位移 (80,48)，实测完全一致。

### 4.2k 测试工具误删用户数据（严重，已修）

冒烟测试**三次删光了用户的真实导图**。根因有三处，都是"无差别删光所有文档"：

1. `reset_workspace()` 清空列表；
2. 第 3 段开头的"保证干净起点"清理；
3. 第 10 段"删除导图"点的是列表里**第一个**。

修法：测试开始时记下既有文档 id（`foreign_ids`），所有清理只删不在这个集合里的。
**并且采集失败时一律不删**（`foreign_ok` 标志）——宁可不清理，也不能误删。

**踩坑记录**：`foreign_ids` 最初在打开面板**之前**采集，那时 `window.__mindmap`
还不存在，异常被 `except` 吞掉 → 当成"列表为空" → 清理把用户数据全删了。
采集点必须放在面板打开之后，且失败要显式标记而不是静默降级。

另外给删除按钮加了 `data-mm-doc` 属性，测试按 id 精确删，不再按位置点。

### 4.2l drawio 导入（用户文件，v0.6.0）

### 4.2m 框选与批量操作（用户需求，v0.7.0 新增）

- **Shift / Cmd / Ctrl + 点击**：累加或减选；
- **空白处拖动**：拉出虚线框，框住（相交即算）的节点全部选中；
- **拖动任一选中节点**：整组一起移动；
- **属性面板**：多选时自动切"批量"模式，改配色/字号/字形/圆角/边框作用于全部选中。

**选择模型**：`selectedId`（主选中，编辑与键盘操作用）+ `selectedIds`（全部选中）。
保留 `selectedId` 而不是只留数组，是因为"加子节点""缩进""原地编辑"天然是针对
一个节点的，有明确锚点比每次取 `ids[0]` 更不容易出错。

**批量拖动用"增量"而不是绝对坐标**：一次拖动要同时移动一组节点，
增量对每个节点都适用；用绝对坐标会把它们全叠到同一个位置。
没有手动位置的节点以**当前自动布局位置**为基准加增量——否则从没拖过的节点
一被框选就会跳到画布原点。

**实现中修掉的 2 个真实缺陷**：
1. **Shift+点击攒不起多选**：`pointerdown` 里加了选，但随后的 `click` 事件
   又调 `store.select(id)`（单选），刚加进去的立刻被重置。
   实测连点三个，`selectedIds` 长度一直是 1。修法：加选时用一次性标记
   抑制随后那次 click。
2. **拖动结束后多选被缩成一个**：同上，`pointerup` 之后的 click 也会重置。
   同样用抑制标记解决。

**测试教训**：验证批量拖动必须按 **node id** 记录坐标，不能按文字——
空文字节点会互相覆盖，导致"看起来位移对了"其实是读错了节点。

### 4.2n 去掉拖动后的提示（用户反馈，v0.7.1）

拖动节点后原本会弹「已移动，点「重新排版」可恢复自动布局」。用户要求删掉。

理由成立：拖动是高频动作，每拖一次弹一条提示是在制造噪音；而「重新排版」
按钮一直在操作条上，需要时看得见，不该靠 toast 提醒。多选拖动的那条同类提示
也一并去掉了。

### 4.2o 自动保存 / 属性抽屉 / 选中即输入（用户需求，v0.8.0）

#### 自动保存

原来只有 600ms 防抖 + 插件卸载时 flush，**关闭标签页或刷新会丢掉最后一次编辑**；
保存失败后只把 dirty 置回、不重试；也没有任何"存没存"的提示。

现在四件事：

1. **离开页面前落盘**：`visibilitychange→hidden`、`pagehide`、`beforeunload`
   三个事件都挂（没有哪个在全部浏览器/场景下都保证触发），用
   `fetch(..., {keepalive: true})` 发请求——普通请求在页面卸载后会被浏览器中止。
2. **失败自动重试**：退避 2s / 5s / 10s / 30s，封顶复用 30s。
   不重试的话，那些编辑会一直留在内存里直到"下一次操作"，而那次操作可能永远不来。
3. **状态一直可见**：工具栏显示 未保存 / 保存中 / 已保存 / 保存失败，
   颜色 + 文字双重编码（只靠颜色的话色弱用户分不出「已保存」和「保存失败」）。
   失败时点一下可手动重试。
4. **验证方式**：冒烟里"改完**立刻**刷新"（不等防抖），断言内容仍在。
   这是这一块唯一有意义的验收——测"等 1 秒再刷新"等于没测。

**实现中修掉的缺陷**：选中后连打 `abc` 只得 `bc`，首字符丢了。
`useEffect` 在浏览器画完这一帧之后才跑，期间到达的按键落在还显示旧值的输入框上。
改成 `useLayoutEffect`（绘制前同步执行）后不再丢。

#### 属性抽屉

从"画布下方横条"改成**右侧可收起抽屉**（宽 288px）。横条挤占画布高度，
导图一深就得上下滚；抽屉只占宽度，画布高度不变。

- 选中节点自动展开，点 × 收起，**收起不取消选中**，再次选中重新展开；
- 与 Markdown 侧栏并存（右侧同列依次排布，窄屏自动上下堆叠）；
- CSS 上有个坑：`.mm-split-style` 与 `.mm-split-side` 权重相同，
  靠源码顺序覆盖 `width`——放前面会被 42% 覆盖成 544px。

#### 选中即输入

选中节点后直接打字进入编辑，**首字符顶替原文字**（不是追加）——这是导图软件的通用直觉，
想追加可以双击（光标在末尾）。

判定条件刻意收得很紧：长度为 1 的可打印字符、不带 Cmd/Ctrl/Alt、不在输入法合成中
（`isComposing`）。这样 Tab / Enter / 方向键 / Delete / 撤销 / 缩放全部不受影响。

**测试注意**：Playwright 输中文走 `insertText`、不产生 keydown，所以
"选中后打字"必须用 ASCII 验证；真实中文输入会先产生拼音字母的 keydown，路径是通的。

### 4.2p 抽屉与画布同层 + 选中项自动进视野（用户需求，v0.8.1）

用户反馈：打开属性抽屉时，画布应该整体左移，让抽屉不遮挡当前选中的节点。

**先复现再动手**：抽屉本来就是 flex 的独立一列（`drawerLeft == canvasRight`），
并不覆盖画布。真正的问题是——**选中节点本身就不会滚进视野**。深层节点在
x=1334 处，而视口只到 1111；抽屉一开画布再窄 288px，更容易越界。
所以「看起来被抽屉盖住」其实是「选中项本来就在视野外」。

**修法两处**：

1. **选中即滚进视野**：把 `focusNode` 里内联的滚动逻辑抽成
   `scrollNodeIntoView(id)`，在 `selectedId` 变化时调用。用**最小位移**
   而不是居中——居中会让画布每次选中都跳一下，打断用户正在看的位置。
2. **尺寸变化后重新滚**：`ResizeObserver` 观察画布容器，宽度一变就把选中项
   滚回来。**不监听「抽屉开/关」两个布尔**：宽度变化的来源不止一个
   （属性抽屉、Markdown 侧栏、窗口缩放、宿主面板折叠），逐个监听一定会漏。
   一次布局变化里 RO 可能连发几次，用 rAF 合并成一次，避免抖动。

### 4.2q 验证环境隔离（v0.8.1，重要）

发现用户的 3080 在 15:09 重启后**正在实时编辑**（导图节点数 56→57→61→62 持续增长），
而我的验证实例 3099 和它**共用同一个存储文件** `$DSH_HOME/storages/`（不按 profile 分）。
两个进程各有内存副本，谁保存谁覆盖对方——真实数据随时可能被我的测试抹掉。

（新增 `verify/start-isolated.sh`）。隔离实例有自己的 storages 目录，
测试随便建文档都不影响用户数据。实测用户文件在整个验证过程中修改时间未变。

隔离实例首次运行会弹 "Get started" 对话框，遮罩会挡住侧边栏，
`open_panel()` 里加了一次性关闭（真实 profile 下是 no-op）。

### 4.2r 编辑体验四项优化（用户需求，v0.8.2）

1. **编辑框加高加宽**：`input` → `textarea`。原来单行 input 挤在 34px 的方框里，
   长文字只能看到一小截。现在最小高度 40px、按内容自动增高（`height:auto` →
   读 `scrollHeight` → 写回，注意每次都要先重置成 auto，否则越缩越小）。
2. **编辑时能通读全文**：编辑框宽度按草稿的**实测宽度**给（`measureText`，
   夹在 180~360），而不是固定值；方框在编辑态不锁尺寸，跟着输入框一起长。
3. **长文本悬停看全文**：新增 `src/client/NodeTooltip.tsx`。不用原生 `title`
   （延迟约 1 秒、样式不可控、长文本会拉成一条横线），自己画浮层：
   只在**被截断**时弹（`scrollWidth > clientWidth`）、延迟 350ms、限宽 320 可换行、
   挂 `document.body`（画布是滚动容器，放里面会被裁）。
4. **编辑态回车只确认**：原来 `Enter` = 确认 + 顺手加一个同级节点，
   改一段文字就平白多出一个空节点。现在 `Enter` 只提交；要加同级在画布态再按一次。

**修掉的缺陷（用户截图反馈"少文本的编辑框高度宽度失调"）**：
给编辑框设了 `min-width: 260px` 之后，短文本节点（92×34）里套了个 264×62 的输入框，
左右各溢出 86px，看着像"小方框套大输入框"。
修法：宽度改成按内容算（180~360），编辑态方框不锁尺寸、包住输入框。

**另一个坑**：一开始让方框"以中心为基准对称展开"，更好看，但节点靠近画布左上边缘时
会被裁到画布外（root 的 x 只有 32，放大到 206 宽就变成 -25）。
改成保持左上角、向右下展开，永远不会裁到自己。

**连带影响**：回车语义变了，冒烟里三处"Tab → 打字 → Enter → 打字"的建节点流程
（5h / 5j / 5k）依赖了旧行为，一并改成"Enter 确认、再 Enter 加同级"。
5j2 的断言也从"scrollH == scaleH"改成"scrollH == max(scaleH, clientH)"——
内容比视口小时本来就不该有滚动条，那是正确行为。

### 4.2s 右键拖动平移画布（用户需求，v0.9.0）

按住右键拖动可以整体平移画布。左键已经被"选中 / 拖动节点 / 框选"占满，
中键在触控板上按不出来，右键是绘图类工具的通行做法。

实现要点：
- 监听挂在外层滚动容器 `.mm-canvas-wrap` 上，不是画布本身——
  这样鼠标停在节点上、或停在留白处都能平移；
- **每次用"起点 + 位移"重算 scrollLeft/scrollTop**，不做累加：
  累加会积累浮点误差，鼠标移出再移回时容易漂移；
- 方向是"起点 − 位移"（鼠标右移 → 内容跟着右移 → 视口往左看 → scrollLeft 变小）；
- 平移中光标变 `grabbing`，给明确反馈；
- 屏蔽画布上的 `contextmenu`：右键已经是手势，再弹浏览器菜单会打断操作。

### 4.2t 中键平移（用户需求，v0.9.1）

右键之外再支持**中键**拖动平移：右键是绘图工具的通行做法，中键是 CAD / 浏览器用户的
肌肉记忆，两者并存成本很低。

**中键有个必须单独处理的坑**：光在 `pointerdown` 里 `preventDefault()` 不够。
Windows 上的 Chrome / Edge 会在 **mousedown** 阶段进入"自动滚动"模式（出现上下箭头
的小圆圈），一旦进入，后续 `pointermove` 就被它接管，平移直接失效。
所以额外在 `mousedown` 与 `auxclick` 上各拦一次。

冒烟断言里专门加了 `5o6`：派发中键 `mousedown` 与 `auxclick`，断言两者都被
`defaultPrevented`——这类"浏览器默认行为抢走手势"的问题，只测"能不能平移"抓不到。

### 4.2u 复制节点（含子树）（用户需求，v0.10.0）

工具栏「复制节点」或 `Cmd/Ctrl+D`，复制选中节点**连同整棵子树**，插入为它的下一个同级。

**最关键的约束：子树里每个节点都必须换新 id。**
id 是节点在同一文档内的唯一标识，选中、撤销栈、图片归属、Markdown 合并的路径匹配
全都依赖它。复用原 id 会让两个节点共享身份——选中一个同时点亮两个、删一个连带删另一个。
这类问题在**数据层就已经坏了**，界面上却未必立刻看得出来，所以单测直接断言
"全树 id 数量 == 节点数量"。

**不换的只有图片 id**：图片字节按 id 存在磁盘，两份节点共用同一张图是正确语义
（`collectImages` 按 id 去重、`reconcile` 不会误删）。

其它取舍：
- **根节点不可复制**——它没有同级，复制会变成两个根，语义不成立（给 toast 说明原因）；
- **手动摆放过的节点，副本整体偏移 28px**，否则会完全重叠在原节点上，用户看不出复制成功；
  没手动位置的节点不设 position，交给自动布局重排；
- **容量按子树算**：`countNodes(root) + 子树节点数 > MAX_NODES` 才拒绝，不是只看一个节点；
- 多选时逐个复制——每复制一个父级下标就变，`duplicateNode` 每次重新 `locate`，所以不会错位。

### 4.2v 连线文字与改关联（用户需求，v0.11.0）

两个功能，本质是同一个数据模型问题：**连线目前是隐式的**——由父子关系推导，
没有独立的"边"实体。

**没有新建边表。** 给连线单开一张表就要处理"节点删了边怎么办""移动节点边跟不跟"
这类一致性问题。改成：
- **连线文字**挂在**子节点**的 `edgeLabel` 上（表示"从父到我这条线的说明"）——
  边跟着节点走，删节点连带删标签，不需要额外维护；
- **改关联** = 换父节点（`reparentNode`），连线自然跟着变。

#### 连线文字

双击连线（或线上已有的文字）出现编辑框，回车确认、Esc 取消，上限 120 字。
标签渲染在曲线的**贝塞尔中点**——不是两端平均值，所以中点在布局层用
`B(0.5) = (P0 + 3P1 + 3P2 + P3) / 8` 算好，避免渲染层各算一次导致不一致。

#### 拖动连线改关联

拖连线到另一个节点上即改挂。实现要点：
- 线只有 1.5px，叠一条 **14px 透明的命中路径**专门接指针，视觉不变但可点；
- 拖动中画一条跟随鼠标的虚线，让用户看得见在拖什么；
- 松手用 `elementFromPoint` 做命中测试，而不是给节点挂 `onPointerEnter`——
  拖动期间指针被连线捕获了，节点的 enter/leave 不会正常触发；
- **环检测**：不能挂到自己的子孙上（`pathTo(newParent).some(id === 移动的节点)`）；
- 换父级时**展开新的父级**，否则节点挂进一个折叠的父级里，看起来像消失了。

#### 又一次"加字段要同步所有契约函数"

`sameTree`（撤销栈的"内容是否变化"判据）必须比 `edgeLabel`，否则改连线文字
不会入栈、撤销键一直灰着——这和 v0.5.0 漏 `style` 是**同一个坑**。
这次主动补上并加了回归单测，没等它变成 bug。

#### 已知边界

连线文字**不导出到 Markdown**。原因是往返一致性：`toMarkdown` → `parseMarkdown`
要能还原同一棵树，把标签拼进正文会污染节点文字（用户文本里本来就可能含分隔符）。
要做需要给标签设计一种无歧义的语法，目前没做。

### 4.2w 多主题（用户需求，v0.12.0）

一张画布上并列多个中心主题。工具栏「＋ 主题」新增，第一次点击会把当前单主题文档
升级成多主题。

**没有把 `doc.root` 改成数组。** 全项目有 78 处 `.root` 调用，树操作（增删改、缩进、
定位、路径高亮、撤销、复制、连线改关联）全部以"单根"为前提；改成森林要动全部调用点
和所有测试，风险远大于收益。

改成 **`MindDoc.multiTheme` 标记 + 容器根**：
- 单主题（`multiTheme` 未设）：`root` 就是画布上的中心节点，行为一字未变；
- 多主题（`multiTheme: true`）：`root` 退化成**不渲染的容器**，它的 children 才是主题。

这样所有既有逻辑一行都不用改——容器就是个普通节点，只是不画出来。
老文档不需要迁移（没有这个字段就是单主题）。

配套改动：
- `layoutForest(themes)`：**每个主题各自调 `layoutTree`，再纵向堆叠**。
  没有往 layoutTree 里加分支——它只管一棵树，在外面组合不会影响单主题的既有行为。
- `toMarkdownForest(themes)`：每个主题各成一个 H1；带文档标题时文档标题独占 H1、
  主题降为 H2（否则多个 H1 会被渲染器当成并列的一级章节）。
- 新主题用**空文字**并直接进入编辑态：给默认文字"新主题"的话，打字会追加成
  "新主题xxx"，也和 Tab 建子节点的行为不一致。

**已知边界：多主题暂不支持从 Markdown 反向修改。** `parse.ts` / `mergeTree` 都以单根
为前提，多主题要让它们变成森林合并。没做之前**明确拒绝并提示原因**，
而不是让它悄悄按单根合并、把几个主题挤成一棵。

### 4.2x 图片的删除 / 替换 / 说明（用户需求，v0.13.0）

原来只能「− 图片」删掉**最后一张**，没法删指定的、也没法换图。

现在每张图片 hover 时右上角浮出三个按钮：`T` 改说明、`↻` 替换、`×` 删除。

**替换必须原地换。** 做成"删掉再加一张"的话，图片会跑到最后——用户只换了一张，
其它图的顺序却变了。`replaceImage` 只换字节来源（id/type/尺寸），
**顺序和说明都保留**（说明是对这张图的描述，换图后通常仍然成立）。

#### 修掉的两个缺陷

1. **操作条跑到图片左下角、还被裁掉。** 根因是上一条宽泛规则
   `.mm-node span { width: 100%; overflow: hidden }` 同样命中了新加的
   图片容器和操作条：容器被拉成整行宽、按钮挤到左边、溢出被裁。
   改用 `.mm-node .xxx`（权重 0,2,0）压过去。

2. **整个插件加载失败：`node is not defined`。** 我在 CSS 注释里写了反引号
   （`.mm-node .xxx`），它**截断了模板字符串**，后面的 `node` 被当成 JS 变量
   求值。构建不报错（语法上合法），只在浏览器加载时炸。
   这已经是这个坑第三次了——**CSS 注释里绝对不能出现反引号**。
   这次补了一个验证手段：用 Node 把 `lib/client.js` 的 factory 跑一遍
   （stub 掉 React），能在本地直接抓到"加载失败"而不是等到浏览器。

### 4.2y 属性面板显示"当前生效值"（用户需求，v0.13.1）

用户反馈：选中节点后，右侧属性面板不显示它当前的属性值。

根因：面板读的是 `node.style`，而 `style` 只包含**显式设置过**的项。
一个没手动设过样式的节点，面板上字号不高亮、字形不高亮、圆角边框也不高亮——
用户根本不知道它现在是 13 号字还是加粗，可画布上明明有确定的外观。

改成显示 **`effectiveStyle(node, depth)`**：没设置过的项按层级默认值算出来，
对应档位正常高亮，并在标签旁标一个「默认」，让用户知道"这是继承来的，不是我设的"。

几个细节：
- **生效值可能不落在任何档位上**（根节点默认字号 13.5，而档位只有 11/13/16/20；
  圆角默认 6，档位是 0/4/8/14）。这种情况没有可高亮的档位，
  于是显示「当前 13.5」「当前 6」，而不是让用户以为"没设置"。
- **层级必须和布局算的一致**：根 = 0，多主题时再减 1（容器根不参与布局）。
  传错的话面板显示的字号和画布画出来的会对不上。
- **默认值常量与 CSS 对齐**：`DEFAULT_RADIUS` / `DEFAULT_BORDER_WIDTH` 同时出现在
  `styles.ts` 的 `.mm-node` 规则里，单测用正则校验两边一致——否则面板说 6px、
  画布画 8px，没人会发现。

#### 顺带修掉一个一直存在的缺陷

**根节点无法取消加粗。** `bold`/`italic` 原来只存 `true`，`false` 被当成"清除"丢掉。
而根节点默认加粗，于是：面板点 B → 存 `true`（还是加粗）或存 `null`（还是加粗），
两种都没反应，按钮看起来是坏的。

现在 `bold: false` 是**有意义的取值**（`applyStyle` 里只有 `null`/`undefined`/`"default"`
才表示清除）。面板按"生效值"取反，所以点一下就是真的取消。

### 4.2z 编辑框尺寸与光标定位（用户需求，v0.13.2）

**① 编辑框默认太大。** 两个写死的下限叠加：`min-height: 40px`（单行只有约 30px）
和 `editorWidth` 的下限 180px（短节点本身才 92px 宽）。

- 去掉 `min-height`，高度交给自动增高算；
- 宽度下限从 180 改成**节点自己的宽度**——节点本来就是按文字长度算宽的，
  用它当基准，进出编辑态的瞬间宽度不会跳变；
- 还挖出一个更隐蔽的：`.mm-node-input` 是 `box-sizing: content-box`，
  而自动增高用 `height = scrollHeight + 2`，`scrollHeight` **已经包含 padding**，
  于是每渲染一轮就多涨 8px，单行文字也能撑成两行高。加 `box-sizing: border-box` 解决。

**② 编辑态点击文字会退出编辑。** 根因是节点的 `onClick` 里无条件调了
`focusCanvas()`：它把焦点从输入框抢走，输入框 blur → commitEdit → 退出。
`onPointerDown` 早就有 `if (editingId !== null) return` 的保护，**click 这条路径漏了**。
补上之后点击就能正常定位光标。

教训：同一个交互往往有多条事件路径（pointerdown / click / dblclick），
加保护时要把它们**逐条**过一遍，只堵一条会留下看起来"随机"的 bug。

### 4.2aa 节点标识（用户需求，v0.14.0）

给节点打图标记号（⭐ 重点 / 🔥 高频 / ⚠️ 易错 / ❓ 疑问 / 💡 想法 / ⏰ 待办 /
✅ 已掌握 / 🚩 关键），复习时一眼扫出重难点。属性面板最前面一排按钮切换，再点一次取消。

**存 key 而不是 emoji 本身。** emoji 会随系统字体变化，而 key 稳定：
换图标只改 `core/marks.ts` 一处，历史数据不用迁移。

**为什么是固定一组、不让用户随便填 emoji**：
① 自由填写的图标在深浅主题下对比度不可控，可能出现看不清的；
② 固定集合才能做后续的"按标识筛选"；
③ 一组八个够表达常见语义，再多用户也记不住。

**一个节点最多 4 个**：再多就变成一串 emoji，反而看不出重点，还会把节点撑得很宽。

**标识宽度必须算进布局。** `contentSize` 里加了 `marksWidth`
（按 `fontSize * 1.15 * 个数` 估），否则文字会把图标挤出去、或图标压到文字上——
又是一种"算的框装不下画的东西"。单测断言"加标识只变宽、不变高"。

**`sameTree` 又要补一行。** 这已经是第三次了（`style` → `edgeLabel` → `marks`）。
每次加节点字段都必须回来同步这个函数，否则改动不入撤销栈、撤销键一直灰着。

### 4.2ab 双击空白新增主题（用户需求，v0.14.1）

在画布空白处双击 = 新增一个中心主题，新主题直接进入编辑态可以马上命名。

**监听必须挂在 `.mm-canvas-wrap` 而不是 `.mm-canvas`。** `.mm-canvas` 的尺寸等于
布局尺寸（只有节点那一片），用户在布局范围之外的空白处双击时事件根本到不了它——
而"空白区域"在视觉上指的是整个可见画布。第一版挂错了地方，
表现是"点了没反应"，但代码看起来完全正确。

节点 / 连线 / 连线文字的双击都各自 `stopPropagation` 了，所以能冒泡到容器的
双击只可能来自空白区；仍然逐个 `closest` 兜一道，防止以后哪个子元素忘了挡事件。

#### 顺带修掉一个会丢数据的缺陷

**撤销「新增主题」会留下坏状态。** 历史快照只存了树，没存 `multiTheme` 标记。
于是撤销后得到"多主题标记 + 单主题树"：多主题模式下根节点是**不渲染的容器**，
真正的根节点凭空消失，画布上一片空白——看起来就像数据丢了。

修法是把 `multiTheme` 纳入快照（`push/undo/redo/reset` 都带上），
`sameTree` 之外再比一次标记。补了单测：撤销回到单主题、重做回到多主题。

**教训**：快照式撤销的隐含前提是"所有影响渲染的状态都在快照里"。
之前只有树，加了 `multiTheme` 这种**影响渲染但不属于树**的标记后，
这个前提就破了。以后再引入类似的文档级开关，都要进快照。

### 4.2ac 双击位置即主题位置（用户需求，v0.14.2）

上一版双击空白是在**自动布局的末尾**追加主题，用户要求"在鼠标双击位置创建"。

三处配套改动：

1. **坐标换算**：画布有 `transform: scale(zoom)`、原点在左上角，所以
   `(clientX - canvasRect.left) / zoom`。直接用 clientX/Y 的话，缩放或滚动后会偏。
2. **`addTheme` 带坐标**：给新主题设 `position`，它就成了"手动摆放"的节点。
3. **`layoutForest` 识别"钉住"的主题**：根节点带 `position` 的主题**不参与纵向堆叠**，
   也不推进堆叠游标——否则加了 `dy` 偏移，坐标形同虚设。
   同时画布尺寸要覆盖钉住的主题（它可能落在堆叠区之外），否则会被裁在可视区外。

**副作用（正面）**：拖拽过的主题本来就会写入 `position`，所以"拖到哪就待在哪"现在
和"双击建在哪就在哪"是同一套规则，不用维护两条路径。

### 4.2ad 连线的两端手柄与删除（用户需求，v0.15.0）

用户反馈：连线改关联"无法操作，不适合快速整理思路"。原来的做法是
**直接拖连线本体**——线只有 1.5px，在密集的图里几乎点不中，而且"两端都能拖"
这件事根本看不见。

改成：**选中节点后，它的入边两端各出现一个可拖拽的圆点，中点出现一个删除按钮。**

- 拖**父端**或**子端**都能改挂（结果一致，只是虚线从另一端画到鼠标，
  看起来就是"你拽着的这一头在动"）；
- 中点 `×` 删除连线 → 子节点（连同子树）**升格成自由主题**，内容一点不丢。

#### 为什么是"升格"而不是"删掉子树"

用户想表达的是"这条关系不成立了"，节点内容本身还是要的。
直接删子树会把辛苦整理的内容一起丢掉。

单主题文档删边时会先升成多主题——自由主题必须和原主题并列，
而并列的前提就是容器根。这和点「＋ 主题」走的是同一次转换。

#### 手柄被节点盖住的坑

第一版手柄放在连线端点（父节点右边缘 / 子节点左边缘）上，**看得见但拖不动**。
原因：节点是绝对定位的 div，在 DOM 里排在 svg 之后，正好盖住圆点，
按下事件到不了它。把手柄沿线往内侧挪 10px，落在两节点之间的空档里就好了。
曲线两端切线是水平的，所以 y 不用动。

### 4.2ae 精简操作条（用户需求，v0.15.1）

用户要求去掉操作条上的「+ 子节点 / ＋ 主题 / + 同级 / + 图片 / − 图片 / 复制节点」
和那句「可粘贴 / 拖入图片」提示。

这些动作都已经有更顺手的入口，按钮是**重复的**：

| 动作 | 入口 |
|---|---|
| 加子节点 | `Tab` |
| 加同级 | `Enter` |
| 加主题 | 双击空白处 |
| 加图片 | 粘贴 / 拖入文件 |
| 删图片 | 图片上悬停的 `×` |
| 复制节点 | `Cmd/Ctrl+D` |

工具条上再摆一遍只会把画布压窄，还要花精力判断"该点哪个"。
现在操作条只剩撤销 / 重做 / 重新排版 / 缩放，画布宽度明显变大。

隐藏的 `<input type="file">` 保留（粘贴、拖入、替换图片都还依赖它），
只是不再有可见的"＋ 图片"按钮去触发它。

#### 测试的连带改动

有 10 处冒烟用例原本是点这些按钮的，改成走各自的真实入口：
`Tab` / `Ctrl+D` / `set_input_files` 到隐藏 input / 双击空白。
其中多主题那几条（5r）测的是**多主题本身的行为**，不是创建手势，
所以直接调 store 的 `addTheme()`，避免双击落到刚建出来的主题上——
创建手势另有 5w / 5x 覆盖。

### 4.2af 连线两端语义 + 自由关系线（用户需求，v0.16.0）

#### ① 拖尾端的语义反了

`1 -> 2` 拖尾端（靠近 2 那头）到 3，用户期望变成 `1 -> 3`，实际却是 `2 -> 3`。

根因：两端用了同一套逻辑（都把"被拖那端所属的节点"挪到落点上）。
但两端语义本来就不同：

| 拖哪端 | 含义 | 结果 |
|---|---|---|
| **尾端**（靠近子节点） | 改这条线**连到谁** | `1->2` 拖到 3 变成 `1->3`，2 升格成自由主题 |
| **父端**（靠近父节点） | 把这个节点**挂到别处** | `1->2` 拖到 3 变成 `3->2` |

修的时候还发现环检测方向写反了（`pathTo(newChild)` 里找 `parent`，应该反过来找），
导致"父级是根节点时任何改接都被拦下"。这个错误在旧语义下被掩盖了。

#### ② 删边后节点不该跳走

原来 `detachToTheme` 会 `delete position`，让它回到自动堆叠——用户看到的是
"删了一条线，节点跑到别处去了"。现在由调用方把当前布局坐标传进来钉住，原地不动。

#### ③ 自由关系线

"每个节点都可以多线连接"——这是**图**的能力，而树模型一个节点只能有一个父级。

没有把整棵树改成图（布局、Markdown 大纲、缩进、方向键导航全部以树为前提），
而是**在树之外加一层关系线**：

- `MindDoc.links: {id, from, to, label?}[]`，不改变树结构；
- 画布上实线 = 层级关系（结构性），虚线 = 关系线（注释性）；
- 选中节点后底部出现一个小圆点，拖到另一个节点就建一条，可连任意多条；
- 点关系线可选中、编辑文字、删除；撤销/重做覆盖。

**几何按相对方位选边**：只按"谁在右边"判断不够——同级兄弟是纵向排的，
两个节点 x 完全一样，那样会画出一条从 A 左边绕到 B 右边的大弯。横向占优就左右连，
纵向占优就上下连。

**历史快照又扩了一次**：`links` 和 `multiTheme` 一样不在树里但影响渲染，必须进快照。
这是同一个教训的第三次复现（style → edgeLabel → marks → multiTheme → links）——
快照式撤销的隐含前提是"所有影响渲染的状态都在快照里"。

#### 交互细节修正

- 删除按钮上移 18px：文字编辑框就在中点上，按钮不挪开会被输入框盖住；
- 连线文字 `pointer-events: none` 并画在节点之上：节点间距只有 54px，
  标签必然比间隙宽，画在节点下面会被裁掉；
- 点**布局之外**的空白也要取消选中——清除逻辑原来只挂在 `.mm-canvas` 上，
  而大片空白属于外层容器；同时用 `suppressClickRef` 挡住框选松手后补发的 click，
  否则刚框好的选中会被立刻清掉。

### 4.2ag 大画布导航：虚拟留白 + 滚动条（用户需求，v0.17.0）

用户在大图（179 节点 / 9 层）上无法到达视野之外的内容："不可见的没办法修改，
也移动不了画布的位置"。

#### 第一次尝试（走错了一步）

把滚动容器整个换成 `transform: translate + scale` 的无限画布——平移量确实无界了，
但**滚动条也一起没了**。滚动条是最熟悉的导航方式，砍掉它等于用一个新问题换旧问题。
用户随即反馈"需要显示滚动条"。

#### 最终方案：虚拟留白

滚动范围 = **内容 + 四周各 4000px 留白**：

- 一个 `.mm-canvas-space` 占位层撑出这个范围（只占位、不显示、不吃事件）；
- 画布定位在 `(PAD*zoom, PAD*zoom)`，缩放仍用 `transform: scale`；
- 于是**滚动条回来了**，而且滚得比内容远得多——内容再大也不会"卡死在边上"。

配套修的三处：

1. **`pointercancel` 不再中断平移。** 右键按下在某些平台会触发系统的上下文菜单手势，
   浏览器随即派发 `pointercancel` 并解除指针捕获，之后 `pointermove` 就再也到不了画布，
   表现正是"右键按住拖不动，位置像被锁住"。现在按下期间在 document 上再挂一份
   `mousemove/mouseup` 兜底。
2. **「居中」按钮。** 画布被拖到看不见内容时的一键退路。
3. **点布局之外的空白也取消选中。** 清除逻辑原来只挂在 `.mm-canvas` 上，
   而大片空白属于外层容器；同时用 `suppressClickRef` 挡住框选松手后补发的 click，
   否则刚框好的选中会被立刻清掉。

**教训**：换掉一个用户依赖的交互范式（滚动条）之前，先确认新方案覆盖了它的全部用途。
无限平移解决了"到不了远处"，但没解决"我不知道自己在哪、怎么回去"。

### 4.2ah 断开连线不变主题 + 节点种类（用户需求，v0.18.0）

用户要求：断开连线后节点**仍然是子节点**（样式、层级、位置都不变），
并且「主题 / 子节点」可以在属性面板里设置。

#### 为什么不能"摘出树"

树模型要求每个节点有父级。把节点从父级摘下来，就只能挂到顶层当主题——
这正是用户不想要的效果。所以加了两个字段：

- `detached`：**连线断开，但节点仍在原父级下**。结构、层级、样式、子树全不变，
  只是布局层不再画那条线。
- `kind`：显式种类（主题 / 子节点）。缺省按结构推断（顶层 = 主题）。

#### 一个关键取舍：断开时**不要钉坐标**

第一版在断开时把节点当前的布局坐标写进 `position`，结果节点反而跳了 32px——
钉坐标本身是多余的：**断开不改变树结构**，自动布局算出来就是原位。
多钉一个手动坐标，只要传入值和布局有偏差就会跳。去掉之后位置分毫不动。

#### 布局层一处判断，所有消费者一致

「断开的线不画」放在 `layoutTree` 生成 links 的地方（`node.detached === true` 时跳过），
画布、导出、测试就都一致了，不用在每个消费者里各写一遍。

### 4.2ai 记住视口位置（用户需求，v0.19.0）

打开导图时恢复上次的滚动位置和缩放，不用每次重新挪画布。

**存 localStorage，不存文档里。** 视口是视图偏好，不是文档内容：
塞进文档会导致"滚动一下 → 文档变脏 → 触发自动保存"，白写磁盘还污染撤销语义。
放本地也只对这台机器有意义（换设备各看各的，本来就该这样）。

三个细节：

1. **恢复要等布局算完**：滚动范围要等画布尺寸定了才有效，
   否则设进去的 scrollLeft 会被浏览器夹到 0。用 `requestAnimationFrame` 延一帧。
2. **同一份文档只恢复一次**：否则每次重排/编辑都会把视图拽回去。
   用 `restoredDocRef` 记住恢复过的 docId。
3. **写入防抖 500ms**：拖滚动条是高频动作，每次都写既浪费又卡。

顺带修了「居中」：原来居中整张布局的包围盒中心，布局一宽就落在两片内容之间的
空白处，点完还是什么都看不见。改成**对准根节点**——那才是内容的起点。

### 4.2aj 内容搜索定位（用户需求，v0.20.0）

按节点正文搜索，快速定位。`Cmd/Ctrl+F` 打开，`Enter` / `Shift+Enter` 在匹配间循环。

设计要点：

- **只搜正文，不搜备注。** 备注不进画布显示，搜到了也看不见，用户会以为定位失败。
- **匹配用 box-shadow 而不是 border 高亮。** border 会改变盒子尺寸，把布局挤动一格。
- **当前匹配和普通匹配两级高亮**：所有命中套浅色环，当前那一个套深色环——
  否则一屏里 5 个同样的环，看不出"跳到哪个了"。
- **跳转 = 选中 + 滚进视野**，复用已有的 `scrollNodeIntoView`，不另写一套定位逻辑。
- **关闭时清空关键词**：否则下次打开还残留上次的搜索，高亮也不会消。

**又踩了一次 TDZ**：搜索块最初插在 `scrollNodeIntoView` 声明之前，
`gotoMatch` 的依赖数组引用了它，直接 `Cannot access before initialization`。
组件里 hook 之间的顺序依赖是隐式的，插代码前得先确认被引用的东西已经声明。

### 4.2ak 自动排版：避让重叠 + 按用户顺序（用户需求，v0.21.0）

用户发来截图：200 节点的图上有多处节点叠在一起，文字互相盖住。

#### 根因

**手动摆放过（拖过）的节点用自己的坐标，自动排布管不到它们。**
拖三五个节点之后，它们和自动节点、以及彼此之间都会叠。

#### 碰撞消解

排完之后加一道后处理：按 y 从上往下扫，发现重叠就把**下面那个连同整棵子树**
往下推，推到刚好不重叠（保留 `gapY`）。只推手动节点——自动节点本来就由排布
保证不重叠，推它们会破坏树的层级感。迭代 4 轮收敛，不做无限循环
（用户真把节点拖成环时，宁可留一点重叠也不能卡死）。

#### 按用户顺序排版

拖动结束后按**视觉上下顺序**重排兄弟节点的 `children` 数组：
用户摆出来的顺序就是他心里的顺序，自动排版应该照着来，而不是照着"输入时的先后"。
只在同一父级的兄弟之间重排，不跨层级、不改父子关系；顺序没变时不产生撤销步。

#### 图片与间距

插入图片后节点变高。自动节点由排布自动重新分配间距；手动节点由碰撞消解
保证不重叠——两条路径合起来，"插了图之后上下间距不一致"就没了。

### 4.2al 连线：独立对象 + 连接点位置 + 线型（用户需求，v0.22.0）

#### 线是独立对象

`selectedIncomingLink` 原来回退到"选中节点就带出它的入边"，于是选中节点时
线上会冒出一个删除按钮和两个端点手柄——用户想改节点，结果很容易误删线。
现在只认 `selectedEdgeId`：**想改线就点线本身**。

#### 连接点只在左右两端

自由连线的起点小圆点原来在节点底部中点。用户的原话是"连接点在方框前后两个位置，
不在上下位置"。挪到**右边缘中点**，和父子连线的端点统一。

#### 折叠按钮移进节点内

`.mm-fold` 原来绝对定位在右边框上，正好压着连线端点——两个小圆挤在一起，
点折叠误拖线，点端点误折叠。改成 inline 跟在文字后面。

#### 线型

`MindNode.edgeStyle`（每条线） + `MindDoc.linkStyle`（文档默认）。
选中线时出现「实线 / 虚线」两个 chip；改一次就记成文档默认，
后面新加的线跟着走，不用每根都调。

### 4.2am 自由连线：线型可改 + 端点只在左右（用户反馈，v0.23.0）

用户："自己拉出来的线，为什么是虚线，而且无法修改线样式，同时我之前要求接线的位置不能在节点的上下位置"。

#### 三个问题都是"漏了自由连线"

上一轮 v0.22.0 做的 `edgeStyle` / `linkStyle` 只覆盖了**父子连线**，
自由连线（`MindDoc.links`）完全没接进去：

1. 样式写死在 CSS 里（`stroke-dasharray: 6 4`），所以永远是虚线；
2. 没有开关，所以改不了；
3. 端点按"横向距离 vs 纵向距离"选边，两个上下相邻的节点就变成竖线、
   端点落在顶部和底部——正是用户明确不要的效果。

#### 修法

- `MindLink.style` + 渲染时 `data-style`，默认实线；
- 选中自由连线时出现「实线 / 虚线」chip，和父子连线同一套；
- 端点**一律走左右边**，按相对 x 决定从哪一侧出发，不再看纵向距离。

#### 顺带：反引号门禁

修这个 bug 时又踩了一次"CSS 注释里的反引号终止模板字符串"——**第四次**。
加了门禁 `styles.ts: CSS 注释里没有反引号`，只扫模板字符串内部的行
（文件头的 JSDoc 在字符串外面，有反引号无害）。

### 4.2an kind 与结构必须一致（用户反馈，v0.24.0）

用户："断开连线后节点变成了主题节点，但连线之后，依然还是主题节点的样式
（包括 markdown 标识符）并无法修改，导致自动排版等情况都异常。"

#### 根因：同一个事实存了两份，然后走散了

`kind` 是**显式存下来的**，而"是不是主题"其实由**层级**决定。断开时节点被升成
主题（kind = theme），后来重新接回树里，结构变了但 kind 没跟着变：

| 地方 | 读的是什么 | 结论 |
|---|---|---|
| Markdown | 结构（层级） | h1，当成主题 |
| 自动排版 | 结构 | 当成主题单独排 |
| 属性面板 | `kind` | 显示"子节点" |

三处互相矛盾，用户怎么点都改不回来。

#### 修法：kind 只是结构的另一个说法

1. **读盘时按层级校正**（`syncKind`）：单主题时根是主题、其余是节点；
   多主题时容器根是节点、它的 children 是主题、更深全是节点。
   —— 用户现有的脏数据在下次打开时自动修好。
2. **接回树里时清掉标记**（`reparentNode`）：`detached` 和 `kind` 一起删掉，
   交给结构推断，不会再有"结构是子节点、标记是主题"的状态。

**教训**：同一个事实不要存两份。派生得到的东西就别持久化，
否则迟早会出现两个版本打架，而且症状分散在三个不相干的模块里。

### 4.2ao 「子节点」必须真的改结构（用户反馈，v0.25.0）

v0.24.0 只做到"kind 与结构一致"，但**面板点「子节点」仍然没效果**：
`setNodeKind(id, "node")` 只是把 `kind` 改成 "node" 并把节点留在顶层，
结构上它还是主题——Markdown 照样输出 h1、排版照样按主题排。

**层级是结构决定的，改层级就必须改结构。**

现在降级会真的把节点**挂到上一个主题下面**（画布上它上面那个中心节点），
子树一起搬走，`kind` / `detached` 一并清掉交给结构推断。
只剩一个主题时没有可挂靠的父级，直接拒绝并提示。

实测：`# 密炼法` → `## 密炼法`，层级 d=1 → d=2。

**教训**：改"身份"类字段时，先问一句"这个字段是派生的吗"。如果是，
改它没用——得改它所派生的那个源头。

### 4.2ap 层级由连线决定（用户规则，v0.26.0）

用户给的规则：

1. 前面连接了其他节点 → **自动识别层级和位置**（父级 = 连线另一端）；
2. 前面没有连接 → **就是 1 级节点**。

这条规则比"挂到上一个主题下面"正确得多：节点之间的从属关系本来就已经由
连线表达了，再按"上面那个"去猜反而错。现在 `setNodeKind(id, "node")` 会：

- 找一条连着它的自由连线（优先 `to === id`，其次 `from === id`）；
- 用另一端当父级，真的把节点搬过去（带防成环检查）；
- 找不到连线就拒绝并提示"它没有连到任何节点，按规则就是 1 级节点"。

### 4.2aq 连线即建立从属（用户需求，v0.27.0）

不用再点「子节点」按钮：**画一条线就自动调整层级**。

规则：连线是 `from -> to`，箭头指向谁，谁就是子节点。只要 `to` 还是主题（1 级），
就把它挂到 `from` 下面；挂靠成功后**这条线不再保留**——父子关系已经用树结构
表达了，再画一条自由连线就重复了。

#### 一个必须区分的概念：「1 级」≠「根的直接子级」

第一版把 `isTop` 写成"父级是根"，结果单主题文档里连两个**普通节点**也被自动挂靠，
自由连线功能等于没了（5A 系列 5 条测试全红）。

正确的判据是**主题**：
- 单主题：只有根自己是主题；
- 多主题：容器根不渲染，它的 children 才是主题。

### 4.2ar 按画布上下顺序插入（用户需求，v0.28.0）

自动挂靠时不再一律追加到末尾，而是**按节点在画布上的 y 插到对应位置**。

用户看到的是纵向排开的一列，新挂进来的节点如果总跑到最下面，
和他眼里的位置就对不上（"我明明把它放到中间了"）。

实现上先算一次原树的布局拿到各自 y，挂进去之后按 y 排序即可。
`layout.ts` 只以 `import type` 依赖 `tree.ts`，所以反向 import 在运行期没有循环。

## 5. 已知边界

- ~~不做自由拖拽画布~~ → **已实现**（v0.1.3，用户要求）。
  节点可拖到画布任意位置并持久化，`position` 是节点上的可选字段；
  不改层级、不改导出的 Markdown 结构。提供「重新排版」一键回自动布局。
  拖动改层级仍走 Tab / Shift+Tab / Alt+←→。
- 不做协作 / 版本历史：单人本地文档，改了就存。
- 撤销只覆盖文档内编辑，不含改名与删文档；历史深度 100 步，不跨文档、不跨刷新。
- 节点文字是纯文本单行（不含富文本）；图片是独立附件，支持图文节点与纯图片节点。
- 图片上限：单张 8MB、单节点 24 张、单文档 200 张；只收 PNG / JPEG / GIF / WebP（不收 SVG）。
- 图片不做裁剪/缩放编辑，只按原始比例等比缩放到节点内的上限尺寸。
- 单文档上限 5000 节点、200 份文档。超限时明确报错而不是静默丢数据。
